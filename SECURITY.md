# Security Policy

## Supported Versions

This framework maintains a rolling release model. Please ensure you are viewing or consuming the latest revision on `main`.

| Version | Supported          |
| ------- | ------------------ |
| 1.x.x   | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Security Vulnerability

If you discover a potential security flaw, vulnerability in recommended patterns, or insecure practice within this framework's checkpoint specifications, please **do not open a public issue**.

Instead, report it responsibly via:
* **GitHub Private Vulnerability Reporting** (preferred, directly via the Security tab of the repository), or
* By emailing the maintainers directly.

### What to Include:
* Specific Checkpoint ID (e.g. `CHK-RES-0501`).
* Detailed explanation of the vulnerability or flaw in the recommended canonical pattern.
* Proof-of-concept (PoC) or exploit scenario where following the checkpoint advice leads to an insecure state.
* Suggested remediation or standard citation update.

We aim to acknowledge reports within 48 hours and provide a fix or clarification within 7 days.
