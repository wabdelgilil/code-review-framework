### 2. Core Rule & Engineering Rationale
* **The Rule:** Newer versions of the codebase must be able to **ingest and process legacy data files and artifacts created by previous stable versions** without crashing or silently corrupting records. Breaking changes to file formats or schema definitions require formal deprecation cycles and explicit migration scripts.
* **Engineering Rationale:** In enterprise software, stored user data and archived reports outlive specific application versions. Deploying a version that cannot parse previously saved data locks users out of their archives and causes immediate downtime.

---

### 3. Quantitative Bounds & Measurable Thresholds
* **Legacy Test Artifact Bank:** Minimum `1` baseline fixture dataset preserved from every previous minor/major release.
* **Backward Ingestion Success Rate:** `100.0%` successful ingestion and parsing of all legacy baseline datasets.

---

### 4. Step-by-Step Verification Protocol
1. **Legacy Test Fixture Suite:**
   * Run automated tests feeding legacy serialized files (v1.0, v1.1) into the current parser.
   * Verify all historical records deserialize cleanly with default fallbacks for newly introduced optional fields.

---

### 5. Binary Pass / Fail Evaluation Criteria
* **`PASS`:** The system ingests and processes all supported historical legacy artifacts without crashing or losing data.
* **`FAIL`:** The system throws unhandled exceptions or corrupts data when reading artifacts generated by earlier software versions.

---

### 6. Canonical Patterns & Code Comparison

#### ❌ Non-Compliant Anti-Pattern (Hard Requirement on Newly Added Fields)
```python
# Prohibited: Adding a new field breaks parsing of all existing legacy records!
class ConfigV2:
    def __init__(self, data: dict):
        self.host = data["host"]
        # Legacy configs generated yesterday did not have 'timeout_ms' -> CRASHES!
        self.timeout_ms = data["timeout_ms"]
```

#### ✅ Compliant Canonical Pattern (Backward-Compatible Schema Ingestion with Fallbacks)
```python
# Compliant: Graceful fallback for historical payloads lacking newer attributes
from dataclasses import dataclass

DEFAULT_TIMEOUT_MS: int = 5000

@dataclass(frozen=True)
class ServiceConfig:
    host: str
    timeout_ms: int = DEFAULT_TIMEOUT_MS

    @classmethod
    def from_dict(cls, data: dict) -> "ServiceConfig":
        if "host" not in data:
            raise KeyError("Mandatory field 'host' missing from configuration")
        # Seamlessly backward compatible with v1 configs lacking timeout_ms
        return cls(
            host=data["host"],
            timeout_ms=data.get("timeout_ms", DEFAULT_TIMEOUT_MS)
        )
```
